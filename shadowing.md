# Shadowing — Architecture & State

## Overview

The shadowing system is a self-contained practice module inside the French Tutor webapp. It sits alongside the main chat flow in the left panel under a single **Shadowing** nav item, which opens a hub selection screen rather than jumping directly into an exercise.

---

## Entry Flow

```
[Shadowing nav button]
        ↓
  Shadowing Hub (#shadowing-hub)
  ├── Subject chip selection (or custom topic input)
  └── Mode card selection
        ├── Phrases     → #shadow-view
        ├── Paragraphs  → #paragraph-view
        └── My Content  → #custom-view
```

The hub stores the selected topic in `shadowingTopic` (JS variable). This value is passed to all backend phrase/paragraph generation calls. When the user navigates back to the hub by clicking "Shadowing" in the nav, the last topic and any saved library state are preserved.

---

## Mode: Phrases (`#shadow-view`)

### Frontend
- **View:** `#shadow-view`
- **JS state:** `currentPhrase`, `currentAudioUrl`, `shadowDifficulty` (1–4), `shadowPassStreak`, `isPhraseLoading`
- **Auto-advance:** after 3 consecutive passes, difficulty increments automatically
- **Blur toggle:** hides the phrase text for pure listening practice
- **Mic:** Web Speech API (fr-FR), 2s silence timeout triggers submission

### Backend
- **Route:** `POST /shadow/phrase`
- **Model:** `mistral-small-latest`
- **Engine:** `shadow_engine.py` → `generate_phrase(difficulty, topic)`
- **Difficulty word counts:** 1=3–5 words, 2=5–7, 3=7–10, 4=10+
- **Topic:** passed as natural language clause appended to the Mistral prompt (e.g. `"…about la nature"`)
- **Scoring:** `POST /shadow/analyze` → `score_attempt()` in `shadow_engine.py`
- **Feedback:** per-mismatch tips generated by `analyze_mismatches()` using `mistral-small-latest`

### Scoring logic (`shadow_engine.py`)
- Normalizes elisions (j' → je, etc.) before comparison
- Word-level alignment with difflib
- Pass threshold: ≥ 0.75
- Returns: `score`, `passed`, `display_results` (word-level diff), `feedback` items

## Mode: Paragraphs (`#paragraph-view`)

### Frontend
- **View:** `#paragraph-view` (has `position: relative` — required for tray positioning)
- **JS state:** `paragraphSentences`, `paragraphLevel` (A1–C1), `paragraphTopic`, `paraStage`, `paraChunkIndex`, `paragraphChunkScores`, `paragraphMismatches`, `paraPassCount`
- **Sentence drill state:** `isSentenceDrill`, `sentenceDrillIdx`, `drillAudioUrl`, `lastSentenceScores`, `lastSentenceStart`
- **Stage progression:** 0=listen full paragraph → 1=shadow 1 sentence at a time → 2=shadow 2 sentences → … → N=whole paragraph
- **Level-up:** after 3 passes at a level, triggers pattern summary overlay then level-up modal
- **Blur toggle, score ring, chunk highlighting:** all present

### Backend
- **Route:** `POST /paragraph/start` → `generate_paragraph(level, topic)` in `paragraph_engine.py`
- **Topic:** if `req.topic` is provided it is used directly; otherwise `random.choice(TOPICS)`
- **Current `TOPICS` list in `paragraph_engine.py`:**
  `["la météo", "la nourriture", "les événements", "la nature", "le marché", "les transports", "la famille", "les loisirs"]`
- **Scoring:** `POST /paragraph/analyze` → `score_chunk()` in `paragraph_engine.py`
- **Pattern analysis:** `POST /paragraph/analyze-patterns` — rule-based + AI patterns via `mistral-large-latest`

### Per-sentence scores (`#para-sentence-scores`)

After every multi-sentence chunk attempt, a panel appears below the feedback showing each sentence in the chunk with its individual score, a colour-coded mini progress bar, and a **Practice** button. Scores are computed entirely client-side from `data.display_results` (word-level diff returned by `/paragraph/analyze`) using `computeSentenceScores()`:

- `display_results` is partitioned by sentence word-count to isolate each sentence's matched/total ratio
- Pass threshold mirrors the chunk threshold: ≥ 0.75 → green, otherwise red
- The panel is hidden on `idle` (new chunk loading) and `complete` states; it persists across retries of the same chunk so the student can see whether their second attempt improved specific sentences

### Chunk pass — manual Continue

When a chunk attempt passes (score ≥ 0.75), the state machine enters `feedback-pass` and shows a **Continue →** button (`#para-controls-pass`) rather than auto-advancing. The user can use this pause to practice individual sentences via the drill tray before moving on. Clicking Continue calls `advanceToNextStage()` directly.

Previously this was a 1.5s auto-advance via `scheduleParagraphAdvance(1500)`. The `scheduleParagraphAdvance` function is still defined (used by `fetchNextParagraph` to cancel any in-flight timer on paragraph reload) but is no longer called on pass.

### Sentence drill tray (`#para-sent-drill-tray`)

A 480px panel that slides in from the right edge of `#paragraph-view` using `transform: translateX(100%) → translateX(0)` (28ms cubic-bezier). Opened by clicking **Practice** on any row in the per-sentence scores panel; closed with the ✕ button, by clicking the backdrop, or automatically when the user moves to the next chunk or retries the whole paragraph.

**Backdrop (`#para-drill-backdrop`):** a full-bleed `position: absolute; inset: 0` overlay (`rgba(0,0,0,0.35)`, z-index 9) that greys out the paragraph view when the tray is open. Clicking it calls `exitSentenceDrill()`. The tray sits at z-index 10 above the backdrop. Both elements live inside `#paragraph-view` (which has `position: relative`).

**Tray contents:**
- Sentence text
- Replay button + Mic button (same `para-replay-btn` / `para-mic-btn` CSS classes)
- Live transcript while recording
- Score bar + percentage + pass/fail label
- Word-level diff and per-word pronunciation tips (same `feedback-item` CSS)

**Key isolation guarantees:**
- `isSentenceDrill = true` while tray is active — `handleParaResult` immediately routes to `handleDrillResult()` instead of the chunk scoring path
- Drill scoring calls `POST /paragraph/analyze` with `chunk_size: 1` and only the drilled sentence as `target`; it **never** writes to `paragraphChunkScores`, `paragraphMismatches`, or triggers stage advancement
- `renderParaFeedback` checks `isSentenceDrill` before calling `setParaState` so the main chunk state machine is untouched
- Recognition `onend`/`onerror` handlers check `isSentenceDrill` before resetting chunk state to `idle`
- `recognition.onresult` silence-timeout checks both `para-mic-btn` and `para-drill-mic-btn` for the `listening` class, and routes the live transcript to either `para-live-transcript-text` or `psdp-live-transcript-text` accordingly
- Both `closeDrillTray()` and `exitSentenceDrill()` remove the `.open` class from both `#para-sent-drill-tray` and `#para-drill-backdrop`

## Mode: My Content (`#custom-view`)

### Frontend
- **View:** `#custom-view`
- User pastes French text + optional label
- Two actions: **Save & Practice** (persists to library then starts exercise) or **Practice (don't save)**
- Saved library rendered from `/custom/list` — each entry has Practice + Delete buttons
- On practice: switches to `#paragraph-view` and runs through `startCustomPractice(text)`, which reuses the full paragraph exercise flow

### Backend
- **Persistence:** `user_content.json` in project root (server-side JSON file)
- **Entry shape:** `{ id, label, text, sentences[], created_at }`
- **Sentence splitting:** `_split_sentences()` — regex split on `.`, `!`, `?` followed by whitespace
- **Routes:**
  - `GET /custom/list` — returns all entries, adds `sentence_count`
  - `POST /custom/save` — splits sentences, writes to `user_content.json`
  - `DELETE /custom/{id}` — removes entry by UUID
  - `POST /custom/start` — splits text, generates TTS for full text, returns `{ sentences, full_audio_url }` (same shape as `/paragraph/start`)

### Key detail
`startCustomPractice(text)` bypasses `/paragraph/start` entirely and calls `/custom/start` directly, then sets up the same JS paragraph state (`paragraphSentences`, `paraFullAudioUrl`, etc.) and calls `startContextStage()`. The paragraph view's existing score ring, chunk shadowing, feedback, and level-up logic all work unchanged.

## Subject / Topic System

### Hub chips (frontend)

| Display Label | French topic passed to backend |
|---|---|
| Nature | `la nature` |
| Restaurant | `au restaurant` |
| Greetings | `les salutations` |
| Hobbies | `les loisirs` |
| Weather | `la météo` |
| Family | `la famille` |
| Transport | `les transports` |
| Market | `le marché` |
| *(Custom input)* | any string the user types |

The selected topic is stored in `shadowingTopic` (JS) and sent with every `/shadow/phrase` and `/paragraph/start` request. Custom topics work because the backend accepts any string and passes it directly to the Mistral prompt.

## Known Issues / Pending Work

### Elision scoring bug (NEXT_STEPS.md item 1)
`t'as`, `t'es` and similar pre-avoir/être elisions score incorrectly because the normalization table maps `t'` → `te` universally. The fix is a pre-substitution step before `_ELISION_RE.sub()` fires, in both `shadow_engine.py` and `paragraph_engine.py`.

### Sentence splitter is naive
`_split_sentences()` in `server.py` splits on `.!?` + whitespace. This breaks on abbreviations (`M. Dupont`), ellipsis (`...`), and decimal numbers. Fine for clean pasted text; should be replaced with a proper sentence tokenizer (e.g. `nltk.sent_tokenize` with `language='french'`) if users start hitting issues.

### No language validation on My Content
The user can paste English or any other language — there is no check. Planned: call `mistral-small-latest` to verify the text is French before accepting, and return an inline error if not.

### Custom content has no "next" after completion
When a custom paragraph exercise finishes, the "Next Paragraph" button calls `fetchNextParagraph()` which generates an AI paragraph at the current level. This is acceptable as a fallback but not ideal. Future: track `isCustomMode` flag and show a "Practice again" / "Back to library" UI instead.

### Topics list in `paragraph_engine.py` is not in sync with hub chips
The `TOPICS` fallback list in `paragraph_engine.py` has 8 items; the hub has 8 chips but with slightly different French strings (`"au restaurant"` vs `"la nourriture"`, `"les salutations"` not in `TOPICS`). This is fine — the hub always sends an explicit topic, `TOPICS` is only used when no topic is sent (e.g. direct API calls). But for consistency, consider updating `TOPICS` to match the hub chip values.

## Future Work

- **Add more subjects:** expand the hub chip list. Easy — add a chip + a `data-topic` value. No backend change needed.
- **User-suggested AI topics:** the custom topic input already works for this. Users type any topic, Mistral generates content for it.
- **Confidence threshold + phonetic check:** see `NEXT_STEPS.md` item 2 (pending from pre-shadowing work).
- **My Content library search/filter:** once the library grows, add a text filter input above the list.
- **Practice List integration for paragraphs:** currently "Save to practice list" appears in paragraph feedback but the source phrase is empty string. Wire up the paragraph's active sentence as the source.
- **Offline-capable TTS caching:** currently each sentence chunk generates a fresh TTS call. For custom content that is practiced repeatedly, cache the audio files by content hash.
